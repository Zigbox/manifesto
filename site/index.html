01 · The inversion
Agents invert the economics of software

    

      
Those tools were built for a world where human attention is scarce. For fifty years software has been optimized to get a person from idea to working demo with the least friction. Safety and correctness, with a few noble exceptions, were afterthoughts, because they cost effort that people didn't have.

    

    

      

        
Built for people

        

          
Effort
Scarce. Spend it on the demo.

          
Safety and correctness
Afterthoughts, with a few noble exceptions.

          
Behavior
Trusted, because a person is at the keyboard.

        

      

      

        
Built for agents

        

          
Effort
Nearly free. The careful work is finally affordable.

          
Safety and correctness
Finally necessary.

          
Behavior
Can't be trusted: honest error, misaligned goals, or instructions slipped in by a stranger.

        

      

    

    

      
The first fact makes safe software cheap to build. The second makes it urgent.

      
Today, an agent is exactly as safe as the person who configured it and the least careful tool it can reach. At scale, a catastrophic failure stops being an if and becomes a when:

    

    
a DateTime, not a Boolean. We may already be at that scale.

  


  

    
02 · If you run a business
Three questions before an agent gets near anything that matters

    
    
      
  1. What can it touch by default, and who decided that?
    honest answer: “everything”
    2. 
      
  2. When it's wrong, can you see it and contain it before the damage spreads?
    honest answer: “no”
    3. 
      
  3. When you combine two tools you've each approved, who checked the combination?
    honest answer: “nobody”
    4. 
    

    
If the honest answers are “everything,” “no,” and “nobody,” the exposure is already in your systems.

  


  

    
03 · If you build software
Software for agents is buttoned down

      
Sandboxing the old tools, with containers, permission prompts, and a human in the loop, helps but doesn't solve it. Wrapping unsafe parts does not make a safe whole. Safety has to live in the substrate.

    

      
above all
Composing safe components never silently produces an unsafe system.

      
capabilities
The smallest useful set
Explicit contracts, bounded effects, and no ambient authority: nothing is permitted merely because it is reachable.

      
types
Invalid operations are unrepresentable
Wherever practical, a wrong call cannot be written down, so it cannot be made.

      
failure
Predictable, contained, observable
Refusals say what was refused and why.

      
legibility
Still readable
Agents still need software they can read: clear semantics, honest errors, stable interfaces. What changes is that misuse stops being the easy path.
